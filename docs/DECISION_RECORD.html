3. Decisions

D1 — Base architecture: fork/extend atlas-memory-demo.
Reason: Elastic-blessed, OSS, DLS isolation empirically validated (0.89 R@10, zero leaks), already implements the 3-index + hybrid + supersession + decay + DLS core. Rejected: clean-room (buys months of re-deriving proven code); stay-on-Hindsight-hybrid (doubles operating surface, keeps Postgres+pgvector dependency we want gone). ⚠ Awaiting user confirmation — flagged OPEN in §5.
D2 — Isolation: DLS + per-user API keys.
Reason: server-enforced — an app bug cannot leak across tenants; proven in the atlas eval. Per-index isolation leaks the moment code forgets a filter; dedicated clusters per team are operationally absurd at coding-farm scale.
D3 — OpenAPPA: SPIKE-ONLY (adopt as optional write-guard, never core).
Reason: OpenAPPA is information-flow control ("is this data allowed to go to this destination"), not memory — 0% overlap with the store/retrieval/consolidation architecture. Its only fit: a deterministic guard in front of shared-bank writes (block private facts flowing into the common catalog). Project status is "Preview & RFC — config and wire surfaces may break without shims", so it must not sit on the critical path. Phase-3 spike with a numeric accept/reject gate (blocks ≥95% of seeded private→shared leaks, <10% false blocks on legit shares).
D4 — Consumption contract: Hermes memory-provider plugin + single MCP endpoint.
Reason: Hermes keeps native-speed retain/recall/reflect via the provider API; coding farm + teammates (Claude Code/Cursor/Codex etc.) hit the same service over MCP — one backend, two doors. MCP-everything adds protocol overhead on Hermes's hottest path. ⚠ Awaiting user confirmation — flagged OPEN in §5.
D5 — Tenancy model: every memory doc carries owner_id (user or agent identity) and visibility ∈ {private, team, common}. Recall DLS: private → creator's key only; team → team role key; common → no filter. Common knowledge is copy-on-promote: a user (or OpenAPPA-guarded auto-promotion) explicitly promotes a private fact into the common bank — never auto-shared.

5. Open questions

OQ-1 Base strategy (D1) & contract (D4). Unblocker: user answers the two flagged decisions (or "accept recommendations"). Nothing in Phase 0 depends on them.
OQ-2 ES license. DLS is Platinum. Self-hosted basic license lacks DLS → isolation falls back to app-level API-key→filter middleware (weaker, tested by same leak suite). Unblocker: confirm whether the self-hosted ES runs Platinum (or Elastic-licensed) or we accept the middleware fallback.
OQ-3 Graph arm. Is 2-hop entity recall ever load-bearing for a coding farm? If yes: Neo4j sidecar vs entity-expansion approximation — decide on measured delta, not vibes. Unblocker: replay 100 real recall queries from the current Hindsight bank, count how many were answered only via the graph arm.
OQ-4 ES 9.6. No public 9.6 yet (verified). Re-check release notes at Phase-1 start for anything that deletes app-layer work (workflows/inference changes). Unblocker: time; also query Elastic-internal roadmap via work channels (you are Elastic).

6. Rejected options

OptionWhy rejected
Wait for a native ES "context engine"/memory productIt does not exist as a feature; only a marketing page exists today. Waiting blocks indefinitely with no shipped artifact.
Stay on Hindsight, add ES as shared layer onlyTwo memory stacks to operate (Postgres+pgvector AND ES), two retrieval semantics, migration debt deferred not removed. Reconsider only if OQ-2 resolves "no Platinum".
Adopt OpenAPPA as architectureIt is a guardrail algebra, not a memory system — nothing to adopt architecturally. Kept as optional guard only (D3).
Clean-room ES designAtlas already implements and benchmarked the target architecture; clean-room re-derives proven code at pure cost.

7. Explicit NON-goals (not built)

  • No Hindsight Cloud / SaaS dependency — self-hosted ES only.
  • No auto-sharing of private memories — promotion is always explicit (D5).
  • No OpenAPPA on the critical retain/recall path — optional write-guard at most (D3).
  • No conversation-transcript storage — facts/procedural/episodic indices only, per atlas pattern.
  • No graph database in v1 unless OQ-3 shows the graph arm is load-bearing.
